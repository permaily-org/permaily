---
title: Fields, types and tokens
description: How a query asks for what comes back, how the SDK turns that into types, and what it costs.
---

A query says which emails you want, and it can also say which fields come back. The SDK turns those fields into types, so you skip the prompt, the parsing and the validation.

## Fields

Fields sit next to the query in the [access](/docs/concepts/#what-an-access-answers). A `?` marks a field that can be empty.

```yaml
query: >
  from:(iberia.com OR booking.com OR renfe.es OR airbnb.com)
  subject:(booking OR reservation OR itinerary)
fields:
  is_cancellation: boolean
  cancellation_notes: string?
  refunded: boolean
```

## Types

The SDK turns those fields into types, next to basic info: the sender, date and subject.

```ts
// Generated by the SDK
type TravelBooking = {
  from: string;
  date: string;
  subject: string;
  isCancellation: boolean;
  cancellationNotes: string | null;
  refunded: boolean;
};
```

## Tokens

A token is one processed unit of an email, such as a piece of extracted information. It isn't an LLM token. The [Developer plan](/developers/#pricing) is planned, not available yet, at $0.01 per 1M tokens, pay as you go.

| You ask for | Tokens per email | 1 million emails cost |
| --- | --- | --- |
| Basic info | 1 | $0.01 |
| Basic info with the three fields above | 3 | $0.03 |

These are the only two counts published, so don't work out a price per field from them.
