# Data

What Permaily stores, where, how it is protected, for how long, and who processes it. This is the basis for the privacy policy, the DPA and the subprocessor list.

## F0 (releases up to v0.1.1)

No user data. The enclave keeps only its TLS key and ACME account key in memory; both disappear when it stops. The parent instance logs connection metadata (timestamps, destination host of egress) but never content.

## F1 (deployed since v0.2.0, 2026-11-10)

One test mailbox, compiled into the image (`deploy/enclave.json`), read with a bearer token whose SHA-256 is in the image. Step 2 of F2 retires it (ADR 0026, "The test mailbox: retired"): the release that builds mailboxes per account reads none of it, its token and its address stop working, and the operator deletes its items (`pk=mailbox#test`, and `raw/test/` in the bucket) once a rollback to v0.11.0 is no longer wanted. Mail it ever received was readable with the operator's token and by every release up to v0.11.0, and stays so until it is deleted and those releases' KMS keys are retired.
